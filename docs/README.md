## 如何读本指南（AI 导读）

- **每章骨架固定**：本章目标 → 前置 → 概念/契约 → 完整可运行示例 → 参考表 → 常见错误 → 交叉引用。示例代码均经 `dsl-cli build` 编译验证。
- **两层命名约定**：同一件事有**宿主桥**（权威，`命名空间.函数`，如 `Ws.sendCommand`）与**插件侧包装**（如 `MioWs.sendCommand`）两套名字；包装写错时以宿主桥为准，全量桥索引见 [09 附录](09-附录.md) §D。
- **权威总表只在 09**：命名空间、入口函数、桥索引、常量集中在附录维护，正文只引用。
- **代码引用格式** `文件:行号`（如 `WsBridge.java:174`）均相对 `app/src/main/java/io/takamiya/mio/`，可直接跳转核对。
- 报错时优先查 [08](08-调试与错误处理.md) 错误码表与 [11 §11.10](11-配置页与HostData.md)、[10 §10.11](10-WS服务与游戏联动.md) 的专项排障表。

## 最低环境

- 已安装支持 DSL 的 Mio APK（映射引擎版本号 `MioEngFun.getEngineVersion() == 4`）。
- 插件构建工具 `dsl-cli.jar`（见 [02 插件包与运行环境](02-插件包与运行环境.md)）。
- 注入通道：输入法 / Shizuku / 虚拟手柄（至少一种，见 [06 注入与按键码](06-注入与按键码.md)）。

## 术语

| 术语 | 含义 |
|---|---|
| DSL / `.dsl` | 插件脚本语言，本指南所指的开发者编写语言 |
| 桥（Bridge） | Mio 暴露给脚本的宿主函数，如 `MioEngFun.tap`；全量注册表见 `MioBridgeRegistry.java` |
| 包装模块 | 插件工程里用 `= call("桥名")` 包一层的 `.dsl` 文件，给业务代码提供好写的名字 |
| 快捷键（ShortcutKey） | 悬浮窗上可触摸/开关的功能键，由插件通过 `onKeyInit` 注册 |
| 触发器（Trigger） | 快捷键的激活方式，`BUTTON` / `SWITCH` / `PRESSURE_PLATE` |
| service | 插件包内声明的运行单元，4 种 tag：`MAINSERVICE`（入口）/ `SHORTCUT_KEY`（快捷键）/ `CONFIG`（配置页）/ `WS_SERVICE`（WebSocket 服务） |
| 配置页 | 插件的设置界面，由 `config.dsl` 的 `schema()` 声明，宿主渲染并负责保存（[11](11-配置页与HostData.md)） |
| HostData | 插件已保存配置的存储（key→值），插件只读（`HostData.get`），用户点「保存」才写入 |
| WS / WebSocket | 宿主内建的 MC 基岩版联动服务（默认端口 8000），插件经 `WS_SERVICE` 收发游戏事件（[10](10-WS服务与游戏联动.md)） |
| 功能开关（feature） | 悬浮窗 WS「功能」页的开关项，插件在 `serverInit` 里 `Ws.registerFeature` 注册 |
| 入口函数 | 宿主主动回调插件的 `export` 函数：`loading` / `keyInit` / `onTriggerDown` / `schema` / `serverInit` / `on<事件名>` 等（全集见 [09](09-附录.md) §C） |
