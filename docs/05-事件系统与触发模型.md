# 05 事件系统与触发模型

**本章目标**：讲透「快捷键怎么按 → 插件哪个函数被调用 → 以什么顺序 → 在哪个线程」，以及注册失败/重复时会怎样。

**前置**：[01 总览与原理](01-总览与原理.md) §1.4 服务线程、[04 模块 API 速查](04-模块API速查.md) §1.1。

---

## 5.1 三种触发模型

插件用 `MioEngFun.onKeyInit(title, model, id, description, group)` 注册快捷键时，`model` 决定快捷键的**激活语义**（第 5 参 `group` 是分组标签，见 [04 §1.1](04-模块API速查.md)）：

| `triggerModel` | 物理行为 | 激活时刻 | 关闭时刻 |
|---|---|---|---|
| `"BUTTON"` | 点按型：按下开始、松开停止 | 按下 | 松开 |
| `"SWITCH"` | 开关型：点一下开、再点一下关 | 切换为开 | 再点（关） |
| `"PRESSURE_PLATE"` | 压力板型：按住积累达标才激活 | 长按达到阈值后 | 松开 |

宿主 `FloatingShortcutKey` 依据模型发出对应的手势事件序列：

| 模型 | 按下 时发的事件 | 松开 / 关闭 时发的事件 |
|---|---|---|
| BUTTON | `KEY_PRESS` + `BUTTON_PRESS` | `KEY_RELEASE` + `BUTTON_RELEASE` |
| PRESSURE_PLATE | `KEY_PRESS`；按阈值达标后 `PRESSURE_PLATE_PRESS` + 激活回调 | 未达标→仅 `KEY_RELEASE`；达标→`KEY_RELEASE` + `PRESSURE_PLATE_RELEASE` + 松开回调 |
| SWITCH | 仅 `KEY_PRESS` | `KEY_RELEASE`；翻转开关时再发 `KEY_ON` / `KEY_OFF` + 激活/失活回调 |

> 长按阈值（`holdThresholdMs`）与达标后松开的延时（`releaseDelayMs`）属于宿主按键配置参数；DSL 侧本次注册接口固定为上述 4 个参数。

## 5.2 插件事件入口（DSL 插件写这些函数）

### 通用快捷键事件（任何模型都触发）

```java
export fn Void onTriggerDown()  // 触发器激活：BUTTON 按下 / SWITCH 开 / 压力板达标
export fn Void onTriggerUp()    // 触发器真实松开/关闭后，紧接 onTriggerDown 返回后调用（可选）
```

- `onTriggerDown` 是**阻塞式**：宿主服务线程调用它之后会一直待在其内部，直到触发条件解除。
- 推荐写法是 `while(MioEngFun.isTriggerDown(id)) { … }` 循环，靠 `isTriggerUp(id)` 或循环头部判断退出（见 [07 章](07-从零写示例.md)）。
- `onTriggerUp` 是「收尾」回调，仅当**确实发生了松开**才触发——如果脚本在 `onTriggerDown` 里提前 `return`（例如注入通道未就绪），宿主检测到按键仍处于按住状态，**不会**发 `onTriggerUp`。

### 模型专属事件（仅对应模型触发）

```java
// 仅 BUTTON 类型的快捷键
export fn Void onButtonPress()
export fn Void onButtonRelease()

// 仅 SWITCH 类型的快捷键
export fn Void onSwitchOn()
export fn Void onSwitchOff()

// 仅 PRESSURE_PLATE 类型的快捷键
export fn Void onPressurePlatePress()
export fn Void onPressurePlateRelease()
```

- 宿主注册表记录每个快捷键的 `TriggerModel`，按下/松开时按模型分流调用。
- 这六个函数都是**可选**的：没写也不报错（宿主用「静默忽略」逻辑调用，见 [08 调试与错误处理](08-调试与错误处理.md) 的 `callIfExported`）。

### 实体键事件（外接键盘/鼠标，广播，可选）

```java
export fn Void onKeyOn(String keyCode)   // 实体键按下
export fn Void onKeyOff(String keyCode)  // 实体键松开
```

- 事件源 = 宿主外接键鼠监听引擎（Shizuku `getevent`，见 [09 §F](09-附录.md)）；每次实体键按下/松开**广播给所有已打开插件**（`callIfExported`，未导出静默跳过），`keyCode` 为 Android 键名全称（如 `"KEYCODE_F6"`、`"KEYCODE_NUMPAD_7"`、鼠标键 `"KEYCODE_BUTTON_1"`）。
- 在专用单线程 `dsl-physical-events` 上执行（不占主线程）；脚本可阻塞，但会拖慢**该插件**后续实体键事件。要「按住循环」语义请用绑定触发（5.3.1），不要在 `onKeyOn` 里自己轮询。
- **不会自触发回环**：Mio 的按键注入（Shizuku `InputManager` / IME）不经过内核 evdev，`getevent` 读不到；唯一回环源是虚拟手柄 uinput 设备，监听启动时按设备名黑名单（`Virtual`/`uinput`）排除。

### 调用顺序（一次完整的按下→松开）

```
按键激活
  │  1. 模型专属「按下」  onButtonPress / onSwitchOn / onPressurePlatePress
  ▼
  │  2. 通用「按下」      onTriggerDown()   ← 阻塞，直到松开/关闭
  ▼
确认松开（宿主触发器状态已非激活）
  │  3. 通用「松开」      onTriggerUp()
  │  4. 模型专属「松开」  onButtonRelease / onSwitchOff / onPressurePlateRelease
```

以上全部在 SHORTCUT_KEY 服务的**同一线程**里串行执行（`DslPluginHandle.ServiceThread`），不存在并发访问脚本解释器的问题。

## 5.3 事件如何从悬浮键到达插件

```
FloatingShortcutKey.onTouch（发出 ShortcutEventType）
   │
   ▼
FloatingWindowService.onShortcutKeyAction / onShortcutKeyEvent
   │  对该键判定 isDslShortcut(key)？
   │  ├─ 是（DSL 快捷键）
   │  │   ├─ BUTTON：按下/松开由 KEY_PRESS/BUTTON_PRESS|RELEASE 事件驱动
   │  │   │        （onShortcutKeyAction 里跳过 BUTTON，避免重复）
   │  │   └─ SWITCH / PRESSURE_PLATE：以 handleTriggerEvent(key, model, active) 驱动
   │  └─ 否 → 传统动作系统（shortcutDispatcher）
   ▼
DslEventDispatcher.handleTriggerEvent(key, model, active)
   ▼
DslPluginManager.dispatchTriggerDown/Up(actionId)
   ▼
DslPluginHandle.onTriggerDown/Up(actionId) → ServiceThread.setTriggerActive(id, active)
   ▼
ServiceThread 循环发现活跃触发器 → 按 5.2 的顺序执行插件函数
```

- 快捷键 key 的匹配容忍 `id` 或 `包名.id` 两种形态（取最后一个 `.` 之后做匹配）。
- 触发过程中宿主同时把「激活/失活」状态写进 `MioEngFun.isTriggerDown/Up` 用的状态表（`MioEngFunBridge.triggerStates`），松开时由服务线程或宿主回调复位。
- 分发按注册包名过滤目标插件（`DslPluginManager.resolveOwnerPackage`）——两个插件声明同名 SHORTCUT_KEY 服务（如复制版插件）也不会跨插件串扰；包名未知时回退广播（兼容旧行为）。

### 5.3.1 实体键绑定触发（外接键鼠）

```
MonitorDaemon（每设备一个 getevent；scanDevices 按设备名黑名单排除虚拟手柄）
   │  evdev KEY/BTN（value 0/1）→ IMonitorCallback（binder）
   ▼
InputMonitorEngine（evdev→Android keycode 映射，回调统一切主线程）
   │  androidKeyCode=0（无对应键）直接丢弃
   ▼
DslEventDispatcher.submitPhysicalKey → dsl-physical-events 单线程执行器
   │  1. pressedPhysicalKeys 集合去重（重复 down 丢弃；up 永远放行，不用时间窗——保住快速点按）
   │  2. 查 MioEngFunBridge.physicalBindings（key → [actionId…]）
   │  3. pluginManager.dispatchTriggerDown/Up(actionId)   ← 与 5.3 相同的下游链路
   │  4. pluginManager.dispatchKeyEvent("KEYCODE_X", down) → 所有插件 onKeyOn/onKeyOff
   ▼
ServiceThread 路由 + 5.2 执行顺序（与卡片触发完全一致）
```

- **注册**：插件在 `keyInit()` 里调 `MioEngFun.onPhysicalKeyInit(keyCode, triggerModel, id)`——登记 owner/包归属与触发状态，但**不进 `registeredShortcuts`**，因此**悬浮面板/控制面板不显示卡片**（这正是与 `onKeyInit` 的唯一本质区别）。
- **键名规范**：`F6` 与 `KEYCODE_F6` 等价（trim、大小写不敏感）；空串 = 解绑（返回 `false`，配置页清空即解绑）；仅允许 `[A-Z0-9_]`。
- **id 冲突**：与卡片注册共用全局唯一 id 空间——复制/并存的插件务必加前缀（如 `p_autoAttack`），否则二次注册被拒并触发重复 id 通知（5.4）。
- **按住语义**：down 后无 up = 持续按住，`isTriggerDown` 为 `true`（与卡片按住一致）；监听停止/失败/服务销毁时宿主对所有按住中的实体键补发松开（`releaseAllPhysicalKeys`），防宏卡死。
- **模型**：绑定表记录 `triggerModel`，但下游按缺省 `BUTTON` 解析即可——模型专属钩子（`onSwitchOn` 等）不导出时无差异，通用 `onTriggerDown/Up` 行为与卡片一致（5.2）。
- **配置**：`<id>.physicalKey`（配置页各功能分组内「触发键」文本），保存后重启插件生效；默认键写在各功能 `keyInit` 的 `MioData.getString(..., 默认键)` 里。

## 5.4 注册流程与归属路由

```mermaid
sequenceDiagram
    participant M as DslPluginManager
    participant H as ServiceThread（服务线程）
    participant B as MioEngFunBridge
    M->>H: 启动线程 dsl-service-&lt;包名&gt;.&lt;服务名&gt;
    H->>B: setCurrentShortcutOwner(name)（ThreadLocal）
    H->>H: callExported("keyInit")
    H->>B: onKeyInit(title, model, id, desc, group)
    B->>B: registeredShortcuts.putIfAbsent(id, item)<br/>捕获 owner=当前服务
    B-->>H: true / false（重复 id）
    H->>B: setCurrentShortcutOwner(null)
    Note over H: 进入 10ms 轮询主循环
```

1. Mio 悬浮窗服务启动 → `loadDslPlugins()` 打开所有已安装插件。
2. 对每个 `SHORTCUT_KEY` service 启动服务线程 → 线程首调 **`keyInit()`**（`DslPluginHandle.java:552`）。
3. **注册窗口**：`keyInit` 执行期间宿主用 ThreadLocal 记下「这条注册来自哪个服务」（`DslPluginHandle.java:546-559`），因此即使多个服务并发 `keyInit`，归属也不会错。
4. 插件在 `keyInit()` 里调 `MioEngFun.onKeyInit(...)`，快捷键进入 `MioEngFunBridge.registeredShortcuts`，出现在悬浮快捷键条上。
5. 之后每次用户操作该键，按 5.3 → 5.2 的链路进回调；**宿主按 owner 只把触发发给拥有该 id 的服务**（`DslPluginHandle.java:566-574`），归属未知时回退广播。

### 重复 id 与分组

| 情况 | 行为 |
|---|---|
| 同一 `id` 二次注册 | `putIfAbsent` 拒绝，返回 `false`；记日志并通过通知渠道 `dsl_duplicate_id` 发**一次**系统通知（每次进程运行每 id 只发一次，`MioEngFunBridge.onDuplicateShortcutId`） |
| 不同服务撞 id | 同上——`id` 是**全插件**唯一的，命名建议加服务前缀（如 `autoAttack`、`mc.attack`） |
| `group` 相同/为空 | 仅影响面板分组展示，不参与路由 |

## 5.5 主循环：触发事件怎么被执行

服务线程在 `keyInit` 之后进入轮询循环（`DslPluginHandle.java:563-625`），每轮 10ms：

1. 遍历 `triggerStates`，取出所有 `active=true` 的 id；**owner 不是本服务的直接移除**（防串扰）。
2. 更新 `MioEngFunBridge` 的触发状态（供 `isTriggerDown` 读）。
3. 按模型调**专属按下**：SWITCH → `onSwitchOn`；PRESSURE_PLATE → `onPressurePlatePress`；否则 → `onButtonPress`。
4. 调 **`onTriggerDown`（阻塞）**——脚本在此循环直到自己退出。
5. 脚本返回后检查 `triggerStates`：**确实已松开**（`released`）才补发专属松开 + `onTriggerUp`；否则视为提前 return，不发（`DslPluginHandle.java:591-609`）。
6. 无论是否松开，都把状态复位为 `false`。

异常处理：循环内 `SdlException` → 日志 + 通知（[08 章](08-调试与错误处理.md)）→ `sleep(100)` 后**继续下一轮**，线程不死。

> **SWITCH 的 `onTriggerDown` 特殊性**：开关拨到「开」→ 步骤 3 调 `onSwitchOn` → 步骤 4 进 `onTriggerDown` 并阻塞；此时宿主把状态保持 `active=true`，直到用户再点「关」才把状态改 `false`、脚本循环退出、步骤 5 补发 `onSwitchOff`+`onTriggerUp`。

## 5.6 代码级走读：BUTTON 按下→松开的 40ms

脚本（同模块注册了 `id="fire"` 的 BUTTON 快捷键）：

```java
import mio.utils.MioEngFun
import dsl.System

export fn Void onButtonPress()            { System.logInfo("T", "1 press") }
export fn Void onTriggerDown() {
    System.logInfo("T", "2 down start")
    while(MioEngFun.isTriggerDown("fire")) { MioEngFun.tap("KEYCODE_J", 5); MioEngFun.sleep(10) }
    System.logInfo("T", "3 down end")
}
export fn Void onTriggerUp()              { System.logInfo("T", "4 up") }
export fn Void onButtonRelease()          { System.logInfo("T", "5 release") }
```

用户按下 40ms 后松开，日志顺序：

```
1 press          ← 服务线程：模型专属按下（DslPluginHandle.java:587 分支）
2 down start     ← 同线程紧接调 onTriggerDown（:590），脚本进 while
   …tap/sleep×2…   ← 脚本循环期间，线程被脚本占着
   （用户松开：悬浮键发 KEY_RELEASE → 宿主把 triggerStates["fire"]=false）
3 down end       ← while 条件为 false，脚本退出
4 up             ← released==true（:592）→ 通用松开（:608）
5 release        ← 模型专属松开（:605），随后状态复位
```

对照要点：

- **顺序是硬编码的**：专属按下 → `onTriggerDown` →（真松开才）`onTriggerUp` → 专属松开；同一线程串行。
- 步骤 2~3 之间宿主改不了状态——「松开」只体现为 `isTriggerDown()` 变 `false`（由用户手势线程写状态表，脚本线程读，`ConcurrentHashMap` 安全）。
- 若脚本在 while 内 `return`（没等到松开），**4、5 都不会出现**（§5.5 第 5 步 `released=false`），且状态被强制复位——下一次按下重新开始。
- 日志里时间戳间隔 ≈ 脚本一轮循环时长（`tap(5)+sleep(10)` ≈ 15ms+ 注入耗时）。

## 5.7 宿主短暂保存的事件枚举（供对照）

宿主 `ShortcutEventType` 共 16 个，其中**与 DSL 直接相关的是带 ⭐ 的**：

| 枚举 | 中文名 | 谁消费 |
|---|---|---|
| REGISTER / UNREGISTER | 注册 / 反注册 | 传统动作系统 |
| KEY_ON / KEY_OFF | 开关开启 / 关闭 | SWITCH 翻转 ⭐ |
| KEY_PRESS / KEY_RELEASE | 快捷键按下 / 松开 | 全模型手势 ⭐（DSL 驱动） |
| BUTTON_PRESS / BUTTON_RELEASE | 按钮按下 / 松开 | 仅 BUTTON 模式 ⭐ |
| PRESSURE_PLATE_PRESS / PRESSURE_PLATE_RELEASE | 压力板按下 / 松开 | PRESSURE_PLATE 达标 ⭐ |
| PRESSURE_PLATE_LONG_PRESS | 压力板长按 | **当前未发出**（仅定义） |
| ENGINE_START / ENGINE_STOP | 引擎启停 | 传统动作系统 |
| SHORTCUT_BAR_SHOW / SHORTCUT_BAR_HIDE | 快捷键条显隐 | 传统动作系统（浮窗层） |

## 5.8 保留（暂未接线）入口

以下 DSL 入口**已存在但当前没有事件源驱动**，资料留存、勿依赖：

- `onTriggerAxis(String axis, Int value)` —— 扳机/摇杆轴事件（宿主无回读源）。
- 带参数的 `onButtonPress(String button)` / `onButtonRelease(String button)` —— 手柄按钮事件（与 5.2 无参版本同名冲突，宿主未接线）。

> 已从保留位转正的入口：`onKeyOn/onKeyOff`（实体键，见 5.2 与 5.3.1）、`onEngineStart/onEngineStop`（引擎启停，`DslEventDispatcher.dispatchEngineStart/Stop`）。

写插件时请只依赖 5.2 节列出的入口。

## 5.9 排障

| 现象 | 检查点 |
|---|---|
| 悬浮条上没有我的键 | `config.json` 是否声明 `SHORTCUT_KEY`；`keyInit` 是否 `export`；`onKeyInit` 是否被调到；重装后是否重启悬浮窗服务 |
| 实体键按了没反应 | 设置页「权限与服务」外接键鼠监听开关是否开；Shizuku 是否已授权（未授权=FAILED 不重试）；绑定键名是否规范（`F6`/`KEYCODE_F6`）；功能 `.enabled` 是否关了（关=不注册绑定）；logcat 过滤 `InputMonitor\|MonitorDaemon\|DslEventDispatcher\|MioEngFun`；小键盘键注意 NumLock |
| 实体键触发到了别的插件 | id 是否与卡片注册重名（5.4）；复制版插件是否忘了加 id 前缀（5.3.1） |
| 注册返回 `false` / 通知栏报重复 id | 该 `id` 已被别的服务注册——全局唯一（5.4 表） |
| 按下没反应 | 通知栏有无错误（[08 章](08-调试与错误处理.md)）；`onTriggerDown` 是否 `export`；`while(isTriggerDown)` 条件是否写反 |
| 松开后没跑 `onTriggerUp` | 提前 `return` 不算真松开（5.2 / 5.5）；只有脚本返回时状态已是 `released` 才补发 |
| 一个服务在跑，另一个不动 | 同一插件内所有入口**同一线程串行**（[01 §1.4](01-总览与原理.md)）——长阻塞会饿死后排 |
| 事件偶尔丢/重复 | 宿主侧有 50ms 防抖（`DslEventDispatcher.DEBOUNCE_MS`）；快速连点属正常合并 |

宿主日志关键字：`DslPluginHandle`、`MioEngFunBridge`、`DslEventDispatcher`。
