## 2.1 一个插件工程的目录结构

以 `Desktop\开发\Plugin` 为例：

```
Plugin/
├── build.config.json          # 构建配置：包信息、引擎版本、签名、混淆（由 dsl-cli 读取）
├── keys/
│   ├── public_key.pem         # 公钥（随包发布，签名校验用）
│   └── private_key.pem        # 私钥（仅作者持有，签名用）
├── obf_dict.txt               # 混淆字典（可选，混淆字典文件）
├── res/
│   ├── config.json            # 插件清单：权限、服务声明（4 种 tag）
│   ├── icon.png               # 插件图标
│   └── （其他文件）            # 可选：随包分发的资源（如卡片点九背景 *.9.png），DSL 以 "@res/…" 引用
├── src/script/                # 全部 .dsl 源码
│   ├── main.dsl               # MAINSERVICE 入口（导出 loading()）
│   ├── config.dsl             # 配置页（声明 CONFIG 时才有；导出 schema()）
│   ├── dsl/
│   │   ├── System.dsl         # 引擎内置 System 包装（可选导入）
│   │   └── Net.dsl            # 引擎内置 Net 包装（可选导入）
│   └── mio/
│       ├── utils/
│       │   ├── MioEngFun.dsl      # Mio 核心模块包装
│       │   ├── MioGamepad.dsl     # 手柄模块包装
│       │   ├── MioSensor.dsl      # 传感器模块包装
│       │   ├── MioFloating.dsl    # 浮窗模块包装
│       │   └── MioConfig.dsl      # 配置声明模块包装
│       ├── ws/
│       │   └── MioWs.dsl          # WS 桥包装（23 个，声明 WS_SERVICE 时用）
│       └── shortcutKey/
│           ├── autoAttack.dsl     # 你的功能模块（SHORTCUT_KEY 服务）
│           └── mc/…               # 可再按主题分子目录，一模块一服务
└── build/                     # 构建产物（由 dsl-cli 生成）
    ├── app.signed.zip         # ★ 最终产物，拿去安装
    ├── app.unsigned.zip
    ├── app/…                  # 打包用中间文件
    ├── ast/**/*.ast.json      # 编译出的 AST JSON
    ├── token/**/*.token.json  # 词法 Token
    └── build.log / mapping.json
```

**目录规则（编译期强校验）**：`package` 声明**必须等于文件所在目录路径**（相对 `src/script/`，不含文件名）。例如 `src/script/mio/shortcutKey/autoAttack.dsl` 的首行必须是 `package mio.shortcutKey`，否则报 `package '…' 与目录路径不符`。根目录下的 `main.dsl`、`config.dsl` 不写 `package`。

## 2.2 清单文件：`res/config.json`

声明插件**权限**和**运行服务**。例如：

```json
{
  "plugin": {
    "permission": [
      { "name": "MODIFY_USER_UI",      "desc": "修改用户界面布局和样式" },
      { "name": "NETWORK_ACCESS",      "desc": "访问外部网络资源" }
    ],
    "service": [
      { "name": "main",                     "tag": "MAINSERVICE" },
      { "name": "config",                   "tag": "CONFIG" },
      { "name": "mio.shortcutKey.autoAttack", "tag": "SHORTCUT_KEY" },
      { "name": "mio.ws.bot",               "tag": "WS_SERVICE" }
    ]
  }
}
```

### 四种服务 tag

> `permission` 数组：`name` 只能写引擎内置的 23 个权限名之一（[§2.6](#26-权限说明) 全表）；`desc` 是**作者自己写的**授权面板说明，会原样显示给用户——写清楚这个权限你要拿来干什么，别抄套话。

| tag | 作用 | 宿主会调的入口 | 声明要求 |
|---|---|---|---|
| `MAINSERVICE` | 包级入口 | `loading()`（打开插件时一次） | `name` 用模块路径（通常 `main`） |
| `SHORTCUT_KEY` | 快捷键服务 | `keyInit()` → 触发循环（`onTriggerDown` 等） | **每个要响应快捷键的模块都必须单独声明一条**，`name` = 该模块的包路径（`mio/shortcutKey/autoAttack.dsl` → `mio.shortcutKey.autoAttack`） |
| `CONFIG` | 配置页 | `schema()`（开配置页时）+ `onButton(key)` | `name` = `config.dsl` 的包名（无包声明写叶文件名 `config`）；**不声明 = 不需要配置页**，点「编辑配置」只弹提示、不调 `schema`（避免「函数不存在」报错） |
| `WS_SERVICE` | WebSocket 联动服务 | `serverInit()` → 事件循环（`on<事件名>`、`onWsFeatureToggle`） | `name` = WS 模块包路径；每条声明各开一条服务线程 |

### `name` 怎么写（三条规则）

1. **`SHORTCUT_KEY` / `WS_SERVICE`**：`name` = 目录路径.文件名。`src/script/mio/ws/bot.dsl` → `"mio.ws.bot"`；`src/script/mio/shortcutKey/autoAttack.dsl` → `"mio.shortcutKey.autoAttack"`。
2. **`MAINSERVICE` / `CONFIG`**：宿主按叶文件名找模块（`configModule` 取最后一段），惯例写 `main` / `config`。
3. 声明的 `name` 必须能在 `src/script/` 下找到对应文件，否则该服务启动失败、入口全不执行。

`plugin.permission`：可选。引擎内置的 23 个运行权限之一；`NORMAL` 级安装时自动授予，敏感级在安装后弹出的授权面板中勾选保存（详见 2.6）。

### 服务的启停与重载契约

| 动作 | 宿主行为 | 插件侧影响 |
|---|---|---|
| 安装 / 卸载 | `SdlEngine.install()` 解码落盘 / 移除 | 卸载即失去所有数据 |
| 打开插件（`loadDslPlugins`） | 逐包 `open` → 按声明启动服务线程 | `loading` / `keyInit` / `serverInit` 依次执行 |
| 禁用插件 | 引擎 unload 运行时，**数据保留** | 一切入口停止执行；配置页仍可编辑保存 |
| 重新启用 | 关闭后重新 `open` | 首次加载即读到已保存配置 |
| 保存配置页 | `setHostDataBatch` → `reloadPlugin`（**关闭→重开**） | 所有服务重启，`keyInit`/`serverInit` 重跑（[11 §11.7](11-配置页与HostData.md)） |
| 重装 ZIP | 覆盖安装后需重启悬浮窗服务触发 `loadDslPlugins` | 否则仍跑旧代码 |

## 2.3 构建配置：`build.config.json`

```json
{
  "plugin": {
    "name": "CuO • 氧化铜~",
    "package": "io.cuo.plugin",
    "icon": "res/icon.png",
    "version": "1.0",
    "versionCode": 100
  },
  "engine": { "minVersion": 1, "targetVersion": 2 },
  "signing": {
    "privateKey": "keys/private_key.pem",
    "publicKey":  "keys/public_key.pem",
    "algorithm":  "SHA256withRSA"
  },
  "build": { "compressIcon": true, "compressLevel": 9, "binSplitThreshold": 0 },
  "obfuscation": {
    "enabled": false,
    "preserveNames": ["dsl"],
    "dictionary": [],
    "dictionaryFile": "obf_dict.txt",
    "obfuscateProperties": false,
    "obfuscatePaths": true,
    "obfuscateMethodNames": true,
    "mappingFile": "build/mapping.json"
  }
}
```

要点：

- `package` 是插件的唯一身份（包名），修改它等于新建一个插件；卸载/重装都靠它定位。
- `signing` 使用你自己的 RSA 密钥对。**私钥丢失=无法再签名更新包；公钥随包发布**。
- `obfuscation.enabled` 开启后编译产物会被混淆（路径/方法名打乱），普通开发建议关闭以方便排障。

字段速查：

| 字段 | 作用 | 常改动？ |
|---|---|---|
| `plugin.name` | 插件页显示名（构建日志头 `CuO • 氧化铜~ v1.0 (code=100)` 即取自这里） | 改 |
| `plugin.package` | 插件唯一包名，宿主按它存储配置/授权/数据 | 基本不动 |
| `plugin.icon` | 图标，指向工程内图片 | 可改 |
| `plugin.version` / `versionCode` | 显示版本号 / 整数版本号（构建输出 `(code=…)`） | 每次发布递增 |
| `engine.minVersion` / `targetVersion` | 引擎兼容版本区间，保持工程默认即可 | 不动 |
| `signing.*` | RSA 签名密钥与算法（`build/keys/` 下的 `.pem`） | 不动（丢了无法更新） |
| `build.compressIcon` / `compressLevel` | 图标压缩开关与级别 | 一般不动 |
| `build.binSplitThreshold` | 产物二进制分块阈值 | 不动 |
| `obfuscation.enabled` | **总开关**：开发期 `false`，发布前可开 | 常切 |
| `obfuscation.preserveNames` | 保留不混淆的名字（如 `dsl`） | 一般不动 |
| `obfuscation.mappingFile` | 混淆映射输出路径——报错栈用它还原 | 不动 |

## 2.4 编译打包：`dsl-cli`

插件不是让手机解析 `.dsl` 文本，而是先在**编译期**把 `.dsl` 编译成 AST JSON、再压缩封装成 ZIP，最后签名生成 `build/app.signed.zip`。

### 编译工具

`dsl-cli.jar`（`java -jar dsl-cli.jar`），Windows 直接运行 Java：

```
java -jar dsl-cli.jar help                 # 查看子命令
java -jar dsl-cli.jar build <项目目录>      # 一键 build（含全部子任务）
```

子任务（一条 `build` 依次执行）：`config → clean → lexer → parser → package → obfuscate → pack → sign`。

一次性构建输出示例：

```
BUILD SUCCESSFUL in 2s
  Lexer:    183ms
  Parser:   287ms
  Package:  65ms
  Obfusc:   179ms
  Pack:     240ms
  Sign:     363ms
  Output:   build/app.signed.zip (175.5 KB)
```

### 设备端控制台（开发迭代流程）

调试开发也可以走**设备端 DSL 控制台**流程：把插件工程放到设备存储的

```
/sdcard/程序/MioConfigs/Plugin/
```

目录下，在控制台/终端里执行构建（同一套 dsl-cli 任务），产物同样落到该目录的 `build/`。如此可反复改 `.dsl` → 重建 → 在 Mio 里重开插件，快速迭代。`build/app.signed.zip` 即为最终产物。

## 2.5 安装到 Mio

1. 把 `build/app.signed.zip` 传到手机。
2. 在 Mio 的插件/配置页面选择该 ZIP（文件选择器打开），Mio 调 `SdlEngine.install()` 校验签名并解码安装；安装成功后宿主再从同一 ZIP 把 `res/*` 补抽到插件目录（引擎安装只搬 `config.json`/`icon.png`/`script/**`，`PluginResInstaller` 负责补抽）。
3. 安装成功后，Mio 自动弹出权限授权面板：`DANGEROUS`/有 Root 的 `SYSTEM` 可勾选，点「保存授权」写入引擎授权存储；其余权限按 2.6 自动锁定。
4. 重启 Mio 悬浮窗服务（或重开插件），插件即被加载。

> 只能安装 **ZIP 格式**的插件包；未签名或签名校验失败会提示`插件签名校验失败`。
> **新增/更新 `res/` 资源后必须重新安装插件**（覆盖安装会先清空插件目录，再由宿主重新补抽 `res/*`）。

### 运行时目录（Mio 应用内部）

安装到哪、跑的时候读什么：

```
data/data/io.takamiya.mio/files/
└── plugin/
    ├── .grants.json            # 宿主全局授权存储（包名 → 已授予权限名），跨会话生效
    └── private/
        └── <包名>/
            ├── config.json            # 解出的插件清单（服务声明等）
            ├── res/…                  # 插件资源（宿主安装后从 zip 补抽；"@res/…" 引用的落地位置）
            ├── script/….ast.json.enc  # 加密后的脚本 AST（运行用）
            └── .sec/manifest.json     # 安全清单
```

`config.json` 的 `service` 声明在打开插件时被读取，决定启动哪些服务、加载哪些入口函数。

## 2.6 权限说明

`res/config.json` 中声明的内置权限对应引擎 `Permissions` 清单，按风险分级（共 4 普通 / 6 危险 / 3 签名 / 10 系统，总计 23 项）：

| 级别 | 授权方式 | 数量 |
|---|---|---|
| NORMAL | 安装时自动授予，面板中锁定显示「默认授予」 | 4 |
| DANGEROUS | 授权面板中可勾选，点「保存授权」生效 | 6 |
| SIGNATURE | 锁定不可勾选（需与插件同签名） | 3 |
| SYSTEM | 无 Root 时锁定并提示「需 Root/系统权限」；检测到 Root 后可授权 | 10 |

全部 23 项（取自引擎 `Permissions` 枚举，`config.json` 的 `permissions` 只能写这些英文名）：

| 级别 | 权限名 |
|---|---|
| NORMAL | `READ_BASIC_USER_INFO` · `READ_PUBLIC_DIRECTORY` · `READ_ALL_PLUGIN_MANIFESTS` · `READ_EXECUTABLE_PLUGINS` |
| DANGEROUS | `MODIFY_USER_UI` · `READ_USER_SETTINGS` · `WRITE_USER_SETTINGS` · `WRITE_PUBLIC_DIRECTORY` · `NETWORK_ACCESS` · `MODIFY_WEBVIEW_UI` |
| SIGNATURE | `PLUGIN_DATA_EXCHANGE` · `READ_OTHER_PLUGIN_PUBLIC_PRIVATE_PATH` · `WRITE_OTHER_PLUGIN_PUBLIC_PRIVATE_PATH` |
| SYSTEM | `READ_SENSITIVE_USER_INFO` · `MANAGE_OTHER_PLUGIN_ABSOLUTE_PRIVATE_PATH` · `INSTALL_THIRD_PARTY_PLUGINS` · `UNINSTALL_THIRD_PARTY_PLUGINS` · `SELF_HOT_UPDATE_UNOFFICIAL` · `OTHERS_HOT_UPDATE_UNOFFICIAL` · `BYPASS_SIGNATURE_VERIFICATION` · `BYPASS_ENGINE_VERSION_CHECK` · `INSTALL_AS_SYSTEM_PLUGIN` · `HIDE_FROM_PUBLIC_PLUGIN_LIST` |

> 记忆口径：**读网络/写文件 ≠ NORMAL**——`NETWORK_ACCESS`、`WRITE_PUBLIC_DIRECTORY` 都是 `DANGEROUS`（要用户勾选才生效）；`READ_SENSITIVE_USER_INFO`（账号/资产/Token）是 `SYSTEM` 级。声明前对照上表。

### 授权流程

- 安装成功后 Mio 自动弹出权限授权面板（Material3 BottomSheet）：列出插件声明权限的名称 / 描述与开关；`DANGEROUS` 与有 Root 的 `SYSTEM` 可勾选，其余按上表锁定。
- 面板重新打开时会**读回已保存的授权状态**作为开关初始值；勾选状态的更改进过「保存授权」一次性写入引擎授权存储 `{filesDir}/plugin/.grants.json`（取消勾选=撤销），无需重启插件，运行中的插件会即时同步。
- 之后可在配置页随时调整：权限设置按钮（`btnEdit`）重新打开授权面板；启用开关可禁用/启用插件（禁用插件不加载、执行被阻断，数据保留）。

### 引擎侧授权 API（宿主 Mio 使用，插件开发一般无需关心）

```
SdlEngine.grantPermission(pkg, name);    // 授权（需插件已声明该权限）
SdlEngine.revokePermission(pkg, name);   // 撤销
List<String> SdlEngine.permissionsOf(pkg); // 已授予权限列表（跨会话）
UserMode SdlEngine.userModeOf(pkg);      // 插件用户等级（null = 不限制，等效 ROOT）
```

脚本内可用的权限入口（经 `dsl/System.dsl` 包装）：

```java
import dsl.System

checkPermission(String name)                 // Bool：是否已授权（Permission.check）
permissionStatus()                           // Map：{declared, granted, missing} 全量
permissionStatus(String name)                // Map：单项 {name, declared, granted, description, level, dangerous}
requestPermission(String name, Callback cb)  // 弹 Mio 单权限授权框，cb 收 Bool（工作线程调用可同步等待）
requestPermissions([String] names, Callback cb) // 弹插件授权 BottomSheet，cb 收保存的授权数（Int）
```

> `Permission.request` / `Permission.requestMultiple` 引擎内置默认抛 UNSUPPORTED，Mio 启动时以 `PermissionBridge` **同名覆盖**为真实授权交互（见 [09 附录](09-附录.md) §D）。状态查询与请求见 [03 DSL 语言](03-DSL语言快速上手.md) 内置命名空间。

## 2.8 真实工程的清单长什么样

本项目参考插件的 `res/config.json` 共 **46 条 service 声明**，构成：

| tag | 条数 | 说明 |
|---|---|---|
| `MAINSERVICE` | 1 | `main` |
| `CONFIG` | 1 | `config` |
| `SHORTCUT_KEY` | **44** | **一个快捷键 = 一个模块 = 一条声明** |

```json
"service": [
  { "name": "main",   "tag": "MAINSERVICE" },
  { "name": "config", "tag": "CONFIG" },
  { "name": "mio.shortcutKey.mc.autoAttack", "tag": "SHORTCUT_KEY" },
  { "name": "mio.shortcutKey.mc.autoBow",    "tag": "SHORTCUT_KEY" },
  { "name": "mio.shortcutKey.mc.effectSpeed", "tag": "SHORTCUT_KEY" }
  // …共 44 条 SHORTCUT_KEY，每条对应 src/script/mio/shortcutKey/mc/<同名>.dsl
]
```

**组织原则**：

1. **一模块一服务**：`mio/shortcutKey/mc/autoAttack.dsl` ↔ `name: "mio.shortcutKey.mc.autoAttack"`——文件名、`name` 尾段、快捷键 id 三者对应，44 个功能全部同构，加新功能 = 复制一个文件 + 加一条声明。
2. **`package` = 目录**（`package mio.shortcutKey.mc`），`name` = 目录.文件名——两条规则缺一不可（§2.2、§2.1）。
3. **声明了但找不到文件 / 文件存在没声明**，对应服务都不会启动（入口全不执行且**不报错**，见 [08 §8.4](08-调试与错误处理.md) 静默表）。
4. 权限声明参考：该工程一次声明了全部 23 项内置权限用于联调；**正式插件按需声明**——声明越多，安装时授权面板越吓人，敏感权限还可能被用户拒绝。

配置页的对应关系见 [11 §11.9](11-配置页与HostData.md)（`onSection` Tab 顺序 = service 顺序）。
